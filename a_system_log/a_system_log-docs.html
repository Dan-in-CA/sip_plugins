A System Log Plugin Documentation

About A System Log Plugin

A System Log plugin implement formatted event reporting to console for SIP System, Program, Station Station and Plugin events. The intent is to facilitate developpement of SIP core and plugins, and for system diagnostic. Also usefull when used in conjunction with systemd-journald service to trace historic SIP behavior. Options are provided to select the different groups of events sent to the console.

Using A System Log plugin

This plugin is disabled by default. If you are reading this, A System Log plugin is probably enabled on your system. Otherwise you can enable it using the plugin manager or by setting the group permissions of the a_system_log.py file to executable. Once it is enabled, and the SIP program has been restarted, you can verify it is working by selecting it from the PLUGINS drop down menu of the main program’s web interface. You should be taken to the plugin’s Settings page.

Requirements

    This plugin has no other dependencies.

Configuration

    The following options control SIP events messages sent to the console:

  • System events: SIP start, restart, reboot, Web UI login, system operation mode change (enable / disable, auto / manual mode), system options change, station names change, rain sensor state change, rain delay change, water level change, midnight hello with OS and SIP uptime./li>
  • Program events: Program enable/disable, add, modify, delete, delete all./li>
  • Station events: Station scheduled (set to run) or completed (terminated schedule) with related info (station number and name, start time, duration, program number and name)./li>
  • Stations output: An array representing the new state of all stations relays./li>
  • Water events: Water level, rain sensor and rain delay./li>
  • Plugins alarms and events: General Plugin Alarm signal and this plugin event./li>

    Other options:

  • Mute Web server logs: By default SIP web server send periodic logs messages to the console (stderr) when a session is openned. These periodic messages includes HTTP GET, PUT, POST packets. These message are stored by systemd-journald service. Under normal operation they are not required. Enablig this plugin option will mute them./li>
  • Prepend timestamp to messages: This option will insert an ISO 8601 formatted date and time with millisecond timestamp at the beginning of all messages sent to the console when SIP is started in interractive mode (command line) or during a debugging sessions./li>
